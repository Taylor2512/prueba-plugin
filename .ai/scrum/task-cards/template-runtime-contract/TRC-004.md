# TRC-004 — Separate schema technical identity from visible name

## Objective

Enforce durable schema identity independent from UI labels, ordering and visual accents.

## Required fields

- schemaUid
- type
- name
- displayLabel
- documentId
- pageIndex
- position
- size
- rotation
- readOnly
- positionLocked
- hidden
- required

## Acceptance

- schemaUid is the only durable identity key;
- validators reject duplicate schemaUid and invalid references;
- label/name/order/color are never used as identity;
- migration path for legacy items without schemaUid is explicit.

## Required process

1. characterize current identity authority and weak points;
2. patch validators and normalization;
3. add contract tests for duplicates/orphans/invalid page/type;
4. wire trace to assignment/snapshot/import pipelines.

## Safety

No identity from array index or DOM order.

## Evidence executed — 2026-08-18 (PARTIAL)

- `validateSisadPdfmeTemplate` now enforces schema identity primitives:
	- required non-empty `schemaUid`
	- duplicate `schemaUid` rejection
	- required non-empty `type`
	- `pageIndex` as non-negative integer
	- `documentId` orphan checks against documents registry
- Tests updated in `tests/unit/contracts/portableTemplate.test.ts` covering duplicate schemaUid and invalid shape.

### Why PARTIAL

- Full field matrix (name/displayLabel/position/size/rotation/readOnly/positionLocked/hidden/required) is not fully enforced yet.
- Scope-level duplicate `name` policies remain pending for schema family contracts.

## Evidence appended — 2026-08-18 (residual characterization and field matrix)

- `validateSisadPdfmeTemplate` now validates the canonical field matrix for each schema: non-empty `name`/`displayLabel`, finite non-negative `position`, positive finite `width`/`height` (the runtime size authority), finite `rotation`, and boolean `readOnly`, `positionLocked`, `hidden` and `required` flags.
- Duplicate visible names are rejected only within the same `documentId` + `pageIndex` scope (`DUPLICATE_SCHEMA_NAME`); names remain non-identity labels and `schemaUid` remains the sole durable key.
- Legacy nested schemas receive explicit migration defaults and deterministic `legacy-{page}-{index}` UIDs; no DOM/array ordering is used by canonical validation.
- Tests: `npx vitest run tests/unit/contracts/portableTemplate.test.ts` (9/9), generated source contract checks (4/4), and `npm run typecheck` passed.

### Residual after this slice

- Assignment/snapshot/import consumers still need an end-to-end trace proving that the validated identity and field matrix are preserved at every runtime boundary; this remains the integration portion of TRC-004 and prevents promotion to `PASS` here.
