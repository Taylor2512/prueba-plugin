# TRC-032 — Signature contract linked to user registry

## Objective

Bind signature identity to signerUserId and separate identity/adoption/acquisition/provider/artifact concerns.

## Acceptance

- signature schemas reference signerUserId (or canonical user identity key);
- no duplicated full user identity payload embedded per signature unless explicit cache projection;
- shared infrastructure can support signature and initials without provider coupling.

## Evidence requirements

- round-trip tests for signer references and artifact refs;
- validation for missing/unknown signerUserId.

## Safety

No provider-specific business semantics in core portable schema.
