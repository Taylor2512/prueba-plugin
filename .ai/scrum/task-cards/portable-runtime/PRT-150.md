## Characterized divergence

`createSisadPdfmeInstanceBundle` produces a *clean* bundle but leaves `basePdf` exactly
as the host handed it over. A bundle exported with `basePdf: 'https://…'` cannot be
restored anywhere else.

Worse, `stripSecrets` rebuilds every object from its enumerable keys, so a binary
`basePdf` survives as `{ "0": 37, "1": 80, … }` — unrecoverable once inside the bundle.
Inlining therefore has to happen *before* the bundle is assembled, not after: once the
value is a string it crosses the secret sweep intact. Both halves of that ordering are
pinned by tests.

## Decision

`inlineSisadPdfmeInstanceAssets` converts every reachable `basePdf` — template, template
map and documents, in both `definition` and `resources` — to a base64 data URI.
`createPortableSisadPdfmeInstanceBundle` composes it with the existing builder and
stamps `assetEncoding: 'base64-inline'`, which `isInlinedSisadPdfmeInstanceBundle`
reads back. Download failures propagate; a bundle missing its base PDF is
indistinguishable from a whole one once serialized.
