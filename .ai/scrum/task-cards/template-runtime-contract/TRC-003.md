# TRC-003 — Canonical portable Template JSON contract

## Objective

Define and validate a canonical JSON format with in-content schemaVersion and enough identity metadata for reliable reconstruction.

## Constraints

- schemaVersion must live inside JSON content;
- no filename-based versioning;
- no non-portable runtime objects in durable JSON;
- keep renderer projections derived from canonical portable shape.

## Acceptance

- canonical shape documented with required and optional fields;
- parser/validator path defined (parse -> identify -> version -> validate);
- compatibility policy for legacy shapes defined and testable;
- deterministic normalization rules for ordering documented.

## Required process

1. compare current template authority with target portable shape;
2. define migration boundaries and unsupported cases;
3. add validator tests for minimal/full/invalid cases;
4. map downstream dependencies (snapshot, import/export, schemas, assignments).

## Safety

Do not create parallel JSON format; evolve canonical authority in place.
