# Intake de tareas

## Preguntas obligatorias

1. ¿Cuál es el síntoma observable?
2. ¿Cuál es el comportamiento esperado?
3. ¿Cuál es la prioridad?
4. ¿Qué dominio es responsable?
5. ¿Qué agente lógico debe intervenir?
6. ¿Qué rutas están involucradas?
7. ¿Qué rutas no deben tocarse?
8. ¿Qué estado o identidad debe preservarse?
9. ¿Qué evidencia existe?
10. ¿Existe una task equivalente?
11. ¿Depende de otro módulo?
12. ¿Cuál es el criterio de cierre?

## Rechazar cuando

- no existe síntoma;
- el objetivo es “mejorar todo”;
- el ownership es ambiguo;
- la solución propuesta es un parche visual sobre un error funcional;
- se pide cambiar contratos sin decisión;
- la tarea duplica una completada.
