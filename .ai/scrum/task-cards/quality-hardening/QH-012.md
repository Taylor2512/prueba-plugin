# QH-012 — Gate de PDF completamente monocromático

## Problema

El requerimiento del usuario es eliminar todo tipo de color al exportar PDF. La implementación actual propaga `colorType: grayscale` en los flujos principales, pero hay que demostrar que ningún renderer/plugin o imagen raster vuelve a introducir crominancia.

## Alcance técnico

- Auditar `generator`, `text`, `rectangle`, `line`, `svg`, checkbox/radio/select, tablas, firmas, acciones y plugins host.
- Definir contrato: `grayscale` convierte RGB/hex/alpha a gris Rec.709; overlays de editor, colores de destinatario y bordes de selección jamás entran al documento.
- Clasificar imágenes raster: convertirlas a grayscale si el requisito es literal; si un plugin no puede convertirlas, fallar preflight con razón explícita en vez de afirmar éxito.
- Asegurar que `Designer`, `Preview`, `Viewer`, runtime React y exportaciones multipágina usan la misma opción.
- Añadir preflight que inspeccione opciones incompatibles y telemetry de `colorType` efectivo.

## Pruebas y evidencia

- Unit de `hex2PrintingColor` para RGB, alpha, blanco/negro, colores de destinatario y valores inválidos.
- Fixture con todos los campos de las capturas: fondos amarillo/verde/rojo, SVG, checkbox/radio, firma, imagen y tabla.
- Parsear/renderizar el PDF generado y verificar ausencia de crominancia en operadores y pixeles; no basta con comprobar que el archivo empieza por `%PDF-`.
- E2E en tres browsers y test de regresión que compara export normal vs grayscale sin overlays.

## DoD

Existe un gate automatizado que falla ante cualquier color no permitido y documenta por separado el tratamiento de imágenes raster.

## Evidencia ejecutada — 2026-08-18 (PARCIAL)

### Auditoría de renderers

Se recorrieron todos los `pdf:` de `src/sisad-pdfme/schemas/**` buscando
llamadas de dibujo que no pasen por `hex2PrintingColor`. Aplican correctamente
el modo: `text`, `rectangle`/`ellipse`, `line`, `svg`, `optionGroupPdfRender`
(y por tanto `checkboxGroup`/`radioGroup`). `graphics/image.ts` no emite
operadores de color propios (dibuja un XObject de imagen).

### Dos fugas reales encontradas y cerradas

1. **`hex2PrintingColor` dejaba pasar cualquier color ya construido como
   objeto** (`if (typeof color === 'object') return color;`). Un plugin que
   construyera su color con `rgb()`/`cmyk()` en vez de un hex reintroducía
   crominancia en una exportación declarada monocromática, y ningún test lo
   detectaba. Ahora `neutralizeColorObject` colapsa RGB y CMYK a luminancia
   Rec.709 cuando el modo es `grayscale`; `Grayscale` se deja intacto por ser
   acromático por construcción.

2. **`createDecisionActionPlugin` ignoraba `colorType` por completo**: su `pdf:`
   hacía `pdfLib.rgb(...pdfColor)` con un color constante del plugin. Ahora
   pasa por `hex2PrintingColor` con `options.colorType`.

### Gate automatizado

`tests/unit/contracts/schemas/monochromePdfExport.test.ts` (8/8). No comprueba
la cabecera `%PDF-`: genera el PDF, descomprime los content streams y lee los
**operadores de color reales** (`rg`/`RG`, `k`/`K`). Falla ante cualquier
operador RGB con componentes distintas o CMYK con cromía.

Incluye **control negativo**: el mismo template sin `colorType: 'grayscale'`
DEBE producir operadores cromáticos. Sin él, el gate positivo podría estar
pasando por construcción sin probar nada.

Unit de `hex2PrintingColor`: hex cromático, blanco/negro sin desplazamiento,
los cuatro colores de destinatario, objeto ya construido, modo por defecto y
hex inválido.

**Verificación de que el gate es real**: revertida la corrección del bypass por
objeto, falla exactamente el test "un color YA construido como objeto tampoco
puede saltarse el modo". Restaurado después.

Gates: `npm run lint` PASS · `npm run typecheck` PASS ·
`tests/unit/contracts/schemas` 440/440 (incluye el test de monocromía
preexistente del commit `b3399d6a`, que sigue verde).

### Por qué queda PARTIAL y no PASS

Lo siguiente del DoD original NO está hecho y necesita su propia iteración:

- **Imágenes raster**: no se convierten a grises ni existe preflight que falle
  con razón explícita cuando un plugin no puede convertirlas. Es la parte más
  costosa (requiere decodificar y recodificar el bitmap) y la tarjeta pide
  tratarla y documentarla por separado.
- **Preflight + telemetría de `colorType` efectivo**: no implementados.
- **E2E en tres navegadores** comparando export normal vs grayscale: el gate
  actual es de nivel unitario sobre el PDF generado, que es donde el color se
  decide; falta la vuelta por navegador.
- **Cobertura de fixture completa**: el template del gate cubre text, rectangle,
  ellipse y line. Faltan firma, tabla, imagen y código de barras.

### Decisión registrada

`hex2GrayscaleColor` sigue devolviendo `rgb(l, l, l)` y no el operador
`grayscale()` nativo de pdf-lib. Un `g`/`G` real sería una garantía más fuerte
y más fácil de verificar, pero el test `textAndBarcodeSafety.test.ts` del
commit `b3399d6a` fija deliberadamente `type: 'RGB'`. No se cambia de forma
unilateral: queda como recomendación para decidir con el autor de ese contrato.
