# QH-011 — Nombre determinista del artefacto PDF y template

## Problema

La captura de exportación descarga `[object Object].pdf`. `basePdf` puede ser una URL/string o un objeto de PDF; convertirlo directamente con `String(...)` filtra la representación por defecto de JavaScript.

## Alcance técnico

- Crear un resolver reusable en `src/sisad-pdfme/browser/` o `src/sisad-pdfme/common/` que acepte `unknown` y devuelva un stem seguro.
- Para objetos, priorizar campos explícitos (`name`, `filename`, `fileName`, `title`), después metadatos de archivo del host; nunca serializar el objeto completo.
- Eliminar path, query, hash, caracteres prohibidos, extensión repetida y espacios extremos; aplicar fallback estable (`sisad-pdfme-document` / `sisad-pdfme-template`).
- Consumir el mismo resolver desde `ui/components/Designer/index.tsx`, `ui/components/Preview.tsx` y `react/SisadPdfmePreviewRuntime.tsx`.
- Mantener nombres separados para exportación JSON y PDF, y registrar el nombre final real en eventos.

## Pruebas y evidencia

- Unit: string URL, objeto con `name`, objeto sin metadatos, URL codificada, `.pdf` ya presente, path con query, `null`, `[object Object]` literal.
- E2E: descargar desde Designer, Preview y runtime; assert `suggestedFilename` no contiene `[object Object]`, termina una sola vez en `.pdf` y el payload comienza `%PDF-`.
- Verificar que el nombre no cambia entre Chromium/Firefox/WebKit ni después de recargar el template.

## DoD

No existe `String(template.basePdf)` en rutas de descarga; todos los consumidores usan el resolver y la evidencia enlaza el nombre descargado.

## Evidencia ejecutada — 2026-08-18

**Resolver**: `src/sisad-pdfme/common/documentFileName.ts`. Acepta `unknown`;
de un objeto lee sólo campos de nombre (`name` → `filename` → `fileName` →
`title`) y NUNCA serializa el objeto; quita path/query/hash, decodifica
`%20`, sustituye caracteres prohibidos, retira una sola extensión conocida y
recorta puntos/espacios finales. Rechaza explícitamente el literal
`[object Object]` aunque llegue ya materializado desde un llamante antiguo.
Fallbacks separados: `sisad-pdfme-document` (PDF) y `sisad-pdfme-template`
(JSON).

**Consumidores conectados** (ya no queda `String(basePdf)` en ninguna ruta de
descarga):

- `ui/components/Designer/index.tsx` — PDF y JSON; el evento
  `designer.action.download.pdf` / `.export.template` registra ahora el nombre
  REAL descargado, no una reconstrucción.
- `ui/components/Preview.tsx` — PDF y JSON.
- `react/SisadPdfmePreviewRuntime.tsx` — PDF.

**Unit** (`tests/unit/contracts/browser/documentFileName.test.ts`, 16/16):
URL string, query+hash, URL codificada, `.pdf` ya presente, puntos internos,
objeto con `name`, precedencia entre campos, objeto sin metadatos, literal
`[object Object]`, `null`/`undefined`/número/array/vacío, caracteres
prohibidos, puntos y espacios finales, fallback inservible y determinismo.

**E2E** (`tests/e2e/designer/descarga-nombre-artefacto.spec.ts`, 5/5 Chromium):
lee `suggestedFilename()` real del navegador y verifica que no contiene
`[object Object]`, que la extensión aparece exactamente una vez, que el stem no
lleva caracteres prohibidos, que el payload empieza por `%PDF-`, y que el
nombre es estable entre descargas repetidas y tras recargar el template.

**Verificación de que el gate es real**: se reintrodujo
`String(visibleTemplate.basePdf)` en la descarga del Designer y el spec falló
con `Received string: "[object Object].pdf"`. Restaurado después
(`typecheck` PASS, 5/5 de nuevo).

Gates: `npm run lint` PASS · `npm run typecheck` PASS · unit 480/480 en el
foco (incluye el contrato uno-a-uno regenerado) · E2E 5/5.

**Riesgo residual (fuera de alcance de esta tarjeta)**:
`integration/index.ts:619` (`normalizeTemplateForRuntime`) también hace
`String(template.basePdf || '')`. NO es una ruta de descarga —no genera un
nombre de archivo— pero convertiría un `basePdf` objeto en la cadena
`"[object Object]"` como valor de template. Es un defecto distinto (corrupción
de template, no de nombre) y merece su propia tarjeta.
