# TRC-005 — Registry-driven schema serialization policy

## Objective

Make schema serialization and migration registry-driven per plugin/manifest without switch-per-type duplication.

## Acceptance

- each registered type has default/create/serialize/deserialize coverage;
- serialization policy is declared by manifest/plugin (or equivalent authority);
- type, schemaUid and semantic properties survive round-trip;
- no second schema taxonomy beyond live registry projection.

## Required process

1. map current schema runtime manifest authority;
2. define serialization hooks and migration responsibility per type;
3. add contract tests generated from registry entries;
4. fail closed for unknown or unsupported types.

## Safety

Do not implement type logic in parallel switch trees.

## Evidence executed — 2026-08-18 (PARTIAL)

- Portable preflight now validates schema-level invariants that serialization pipelines depend on (`schemaUid/type/pageIndex/documentId`).
- Canonical parse pipeline (`normalizePortableTemplate`) migrated into structured validation stage and explicit outcomes, reducing ad-hoc parsing behavior.
- Contract tests confirm deterministic behavior for invalid schema payloads and orphan references.
- Portable template validation now fails closed for schema types unknown to the live schema registry.
- Contract tests now cover unsupported schema type rejection against the live registry.

### Why PARTIAL

- Per-plugin serialization hooks (`pick/validate/migrate`) are not yet delegated from live schema registry.
- Full registry-driven round-trip coverage per registered schema type remains pending.

## Evidence appended — 2026-08-18 (registry serialization policy)

- Added `SchemaSerializationPolicy` to the live schema plugin/manifest projection with `serialize`, `deserialize`, `validate` and `migrate` hooks.
- Added `getSchemaSerializationPolicy` and `listSchemaSerializationPolicies`; absent plugin hooks use one registry-owned identity policy, while unknown schema types still fail closed before policy lookup.
- Portable template validation now delegates schema validation to the registry policy, and canonical serialization delegates each schema to its registered serializer.
- Registry-generated contract test covers every built-in definition and verifies identity/type preservation through serialize → validate → deserialize.
- Tests: portable template (9/9), schema registry (6/6), `npm run typecheck`, generated source manifest apply and `git diff --check` passed.

### Residual after this slice

- Built-in plugins currently rely on the registry default policy; plugin-specific semantic serializers/migrations and external registered-plugin round-trip fixtures remain to be added before this card can become `PASS`.
