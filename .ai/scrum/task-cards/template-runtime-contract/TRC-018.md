# TRC-018 — Fail-closed import and migrations

## Objective

Implement strict parse/identify/version/migrate/validate/hydrate pipeline with explicit outcomes.

## Required outcomes

- VALID
- MIGRATED
- UNSUPPORTED
- INVALID

## Acceptance

- unsupported versions fail closed with actionable issue;
- migrations are explicit, versioned and test-covered;
- no try/catch defaults that continue with data loss risk;
- ownership/schemas/assignments cannot be silently dropped.

## Evidence requirements

- contract tests for malformed/unsupported/migrated/valid inputs;
- migration trace in evidence report.

## Safety

Do not auto-heal broken payloads without a migration contract.

## Evidence executed — 2026-08-18 (PARTIAL)

- `normalizePortableTemplate` and `parsePortableTemplate` now return explicit outcomes:
  - `VALID`
  - `MIGRATED`
  - `UNSUPPORTED`
  - `INVALID`
- Fail-closed parse and version handling implemented with structured issues (including JSON parse error and unsupported schemaVersion).
- Legacy payload migration is explicit through canonical migration function before validation.
- Added explicit ingest pipeline helper `ingestPortableTemplate(payload)` with stage trace:
  - `parse -> identify -> migrate -> validate -> hydrate`
  - hydration is skipped when parse/validation fails.
- Added canonical hydration helper `hydratePortableTemplate` to expose post-validation entities.
- Contract tests expanded in `tests/unit/contracts/portableTemplate.test.ts` for ingest trace and fail-closed hydration behavior.

### Why PARTIAL

- Hydration stage integration across runtime entrypoints is still not fully wired as one shared path.
- Dedicated migration trace/evidence artifact in reporting views remains pending.
