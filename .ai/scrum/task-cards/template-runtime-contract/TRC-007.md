# TRC-007 — normalizeUsers/indexUsers/validateUsers authority

## Objective

Create a single authority pipeline for user normalization, indexing and validation.

## Required behavior

- duplicate id -> error
- empty id -> error
- duplicate email -> warning/policy
- invalid activeUserId -> fail closed
- missing displayName -> controlled fallback
- non JSON-safe metadata -> reject

## Acceptance

- one pipeline function set used by import/restore/runtime initialization;
- deterministic behavior and structured issues;
- no identity fallback from array order.

## Safety

Reject functions, Blob/File and cyclic objects in user metadata.

## Evidence executed — 2026-08-18 (PARTIAL)

- Added explicit helpers in `src/sisad-pdfme/contracts/workspace.ts`:
	- `normalizeUsers` (alias)
	- `indexUsers` (alias)
	- `validateUsers` (alias)
	- canonical implementations `normalizeSisadPdfmeWorkspaceUsers`, `indexSisadPdfmeUsers`, `validateSisadPdfmeUsers`.
- Validation now covers duplicate id, empty id, duplicate email (warning), invalid `activeUserId` (error) and non JSON-safe metadata.
- Tests extended: `tests/unit/contracts/workspaceContract.test.ts` validates indexing and active user checks.
